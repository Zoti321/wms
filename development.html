仓脉 WMS 开发设计说明书

本文档给出实现路径：技术栈、分层架构、模块边界、核心表结构、API 约定、状态机、目录规范与上线里程碑。需求细节见 需求文档。

1. 概述与设计原则

  • 单据驱动库存：库存变更只通过领域服务在事务内完成，并写 ledger 流水。
  • 幂等与防超卖：出库确认使用库存行 version 乐观锁；重复提交用业务单号幂等键。
  • 模块内聚：主数据、入库、出库、库存、盘点、权限分离，通过应用服务编排。
  • 先单仓后扩展：表结构预留 warehouse_id，MVP 可固定默认仓。

2. 技术选型（推荐示例）

层级选型说明
前端Vue 3 + TypeScript + Vite + Element Plus管理后台；路由权限 + 表格/表单为主
后端Java 17 + Spring Boot 3REST API；Spring Security + JWT
持久化PostgreSQL 15+ + Flyway事务可靠；迁移脚本版本化
缓存（可选）Redis会话、热点 SKU 查询、分布式锁（可选）

部署Docker Composeapp + db（+ redis）一键本地/测试环境

若团队偏 Node / Go / .NET，可替换实现语言，但库存事务、状态机、流水表设计建议保持一致。

分层约定

  • Controller：参数校验、鉴权注解、DTO 转换，不含业务规则
  • Application：一个用例一个服务方法（如 confirmInboundPutaway）
  • Domain：库存扣减、状态流转校验
  • Infrastructure：仓储实现、外部系统适配

4. 模块划分

mdm · 主数据

SKU、库区库位、供应商/客户、字典。

inbound · 入库

入库单 CRUD、审核、上架确认。

outbound · 出库

出库单 CRUD、审核、拣货确认扣库存。

inventory · 库存

库存查询、流水、预警任务。

stocktake · 盘点

盘点单、盈亏审核、调整入账。

iam · 权限审计

用户角色、菜单权限、操作日志。

5. 数据模型（核心）

5.1 ER 关系（文字版）

Warehouse 1—N Location；SKU 与 Location 通过 Inventory（N—N 关联实体）关联；InboundOrder / OutboundOrder 1—N OrderLine；所有变动写 InventoryLedger。

5.2 关键表（简化 DDL 示意）

CREATE TABLE sku (
  id            BIGSERIAL PRIMARY KEY,
  warehouse_id BIGINT NOT NULL,
  sku_code      VARCHAR(64) NOT NULL,
  name          VARCHAR(200) NOT NULL,
  unit          VARCHAR(16) NOT NULL,
  safety_stock  NUMERIC(18,3) NOT NULL DEFAULT 0,
  status        SMALLINT NOT NULL DEFAULT 1,
  UNIQUE (warehouse_id, sku_code)
);

CREATE TABLE location (
  id            BIGSERIAL PRIMARY KEY,
  warehouse_id BIGINT NOT NULL,
  location_code VARCHAR(64) NOT NULL,
  zone          VARCHAR(32),
  status        SMALLINT NOT NULL DEFAULT 1,
  UNIQUE (warehouse_id, location_code)
);

CREATE TABLE inventory (
  id            BIGSERIAL PRIMARY KEY,
  warehouse_id BIGINT NOT NULL,
  sku_id        BIGINT NOT NULL REFERENCES sku(id),
  location_id   BIGINT NOT NULL REFERENCES location(id),
  qty_on_hand   NUMERIC(18,3) NOT NULL DEFAULT 0,
  qty_available NUMERIC(18,3) NOT NULL DEFAULT 0,
  qty_frozen    NUMERIC(18,3) NOT NULL DEFAULT 0,
  version       BIGINT NOT NULL DEFAULT 0,
  UNIQUE (warehouse_id, sku_id, location_id)
);

CREATE TABLE inventory_ledger (
  id            BIGSERIAL PRIMARY KEY,
  warehouse_id BIGINT NOT NULL,
  sku_id        BIGINT NOT NULL,
  location_id   BIGINT NOT NULL,
  change_qty    NUMERIC(18,3) NOT NULL,
  bal_qty       NUMERIC(18,3) NOT NULL,
  ref_type      VARCHAR(32) NOT NULL,  -- INBOUND / OUTBOUND / STOCKTAKE
  ref_id        BIGINT NOT NULL,
  ref_no        VARCHAR(64) NOT NULL,
  operator_id   BIGINT NOT NULL,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
扣减库存伪代码：UPDATE inventory SET qty_available = qty_available - :q, version = version + 1 WHERE id = :id AND version = :ver AND qty_available >= :q；影响行数为 0 则失败重试或报错。

6. API 设计（节选）

统一前缀 /api/v1；鉴权 Header：Authorization: Bearer <token>；响应包络：

{
  "code": 0,
  "message": "ok",
  "data": { },
  "traceId": "..."
}
方法路径说明
POST/auth/login登录，返回 JWT
GET/POST/skus商品列表 / 创建
GET/POST/locations库位管理
POST/inbound-orders创建入库单
POST/inbound-orders/{id}/approve审核入库单
POST/inbound-orders/{id}/putaway上架确认（增库存）
POST/outbound-orders创建出库单
POST/outbound-orders/{id}/approve审核（可预占/校验）
POST/outbound-orders/{id}/pick拣货确认（扣库存）
GET/inventories按 SKU/库位查询
GET/inventories/ledgers库存流水
POST/stocktakes创建盘点
POST/stocktakes/{id}/approve审核盈亏并调账

7. 单据状态机

入库

DRAFT→ PENDING→ APPROVED→ PUTAWAY→ DONE

任意未完成态可转 CANCELLED（需权限；已上架部分需先定义回退策略，MVP 可限制「未上架才可取消」）。

出库

DRAFT→ PENDING→ APPROVED→ PICKING→ DONE

9. 开发规范

  • 分支：main 保护；功能分支 feature/*；发版打 tag
  • 提交信息：简体中文，说明「为什么」（如：修复出库并发超卖）
  • 接口变更必须更新 OpenAPI；破坏性变更升 /api/v2
  • 库存相关单测：不足拒绝、乐观锁冲突、幂等重复提交
  • 禁止在 Controller 直接改 inventory 表
  • 日志：业务关键路径打 info；异常带 traceId；不落密码明文

10. 里程碑计划

阶段周期交付物
M0 开工第 1 周仓库初始化、CI、登录骨架、表结构 Flyway
M1 主数据第 2–3 周SKU/库位 CRUD、权限菜单
M2 入库闭环第 4–5 周入库单 + 上架 + 库存增加 + 流水
M3 出库闭环第 6–7 周出库单 + 扣减 + 防超卖 + 查询
M4 盘点报表第 8–9 周盘点调账、预警、导出、审计
M5 上线第 10–11 周UAT、性能与并发测试、备份演练、上线

11. 部署与运维要点

  • 环境：dev / staging / prod 隔离；密钥走环境变量
  • 数据库每日备份；恢复演练至少每季度一次
  • 监控：API 错误率、接口耗时、磁盘与连接池
  • 上线检查清单：迁移脚本、回滚方案、只读账号、初始管理员
