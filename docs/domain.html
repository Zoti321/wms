仓脉 WMS 领域模型

交付面（后端 API、网页后台、小程序）是适配器，不是上下文。下文描述业务边界与统一语言；需求与实现必须使用这些术语。

1. Context Map

主数据 catalog

仓库、商品（SKU）、库区/库位、供应商与客户。MVP 只启用一个仓库，模型仍保留仓库为一等概念。

库存 inventory

数量真相：在库 / 冻结 / 可用与库存流水。唯一允许改账的地方；负责库存预警。

入库 inbound

入库单生命周期与上架执行；不拥有数量账。

出库 outbound

出库单生命周期与拣货执行；审核分配、拣货实扣。

盘点 stocktake

盘点单、盘点锁、实盘与盈亏确认。

2. 上下文关系

  • 主数据 → 其余：只引用标识；库存读取安全库存阈值以生成/解除预警。
  • 入库 → 库存：上架确认请求增加在库；记账成功才算上架成功。
  • 出库 → 库存：审核请求分配（可用→冻结）；拣货请求实扣；取消未拣请求释放预留。
  • 出库 → 入库：已实扣纠错不走取消抹账，另开退货入库（或二期冲销）。
  • 盘点 → 主数据 / 库存：盘点锁禁止上架与出库；审核后一次性盈亏调整并释锁。
  • 入 / 出 / 盘：彼此不直接改对方单据，不共享可变库存状态。
上架 / 分配 / 实扣 / 盈亏→ 库存记账→ 库存流水

3. 明确排除（非领域上下文）

  • 身份与权限：用户、角色、菜单/接口鉴权 — 平台支撑。
  • 操作日志：谁点了登录/审核 — 平台审计；不要与库存流水混称。
  • 网页后台 / 小程序 / API：交付与适配，不是限界上下文。

4. 核心术语（摘要）

术语上下文要点
仓库主数据一等概念；单据与库存均归属
安全库存主数据阈值；是否预警由库存判定
在库 / 冻结 / 可用库存可用 = 在库 − 冻结
分配（预留）出库→库存审核时可用→冻结
实扣出库→库存拣货时冻结与在库同减
释放预留出库→库存取消未拣：冻结→可用
盘点锁盘点锁库位作业；≠ 冻结数量
库存流水库存账为何变化；关联单据行
库存预警库存汇总可用低于安全库存
勿混用「冻结」：库位状态冻结 / 盘点锁（空间与作业）≠ 冻结数量（出库预留口径）。
