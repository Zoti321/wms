仓脉 WMS 需求规格说明书

本文档定义仓库管理系统的业务目标、功能范围、角色权限、业务规则与验收标准。术语与上下文边界以 领域模型 为准；实现路径见 开发文档。

1. 引言

1.1 项目背景

企业仓库依赖表格或口头交接时，易出现账实不符、库位混乱、出库差错与追溯困难。需要一套以单据驱动的数字化 WMS，统一管理入库、上架、出库、盘点与库存查询。

1.2 项目目标

  • 库存账实一致率 ≥ 99.5%（按月盘点口径）
  • 出入库单据全程可追溯（操作人、时间、数量、库位、库存流水）
  • 支持低库存预警，减少缺货与积压
  • MVP 在 8～12 周内可上线「单仓启用」的核心流程（模型仍预留多仓）

1.3 范围说明

范围内（MVP）范围外（二期）
仓库/商品/供应商/库位主数据；入库、出库（审核分配 + 拣货实扣）、库存查询与流水；盘点锁 + 简单盘点；角色权限与操作日志；基础报表与库存预警 PDA 扫码、波次拣货、保质期 FEFO、多仓调拨自动化、AGV/立库、与外部 ERP 深度双向同步、红冲单细化

2. 干系人与角色

角色与鉴权属平台支撑能力，不进入领域上下文；下表描述业务职责与典型权限。

角色职责典型权限
系统管理员 账号、角色、基础配置 用户管理、字典配置、全模块只读/授权
仓库主管 审核单据、盘点、报表、异常处理 审核入出库、发起盘点、查看全仓报表
仓管员 执行入库上架、出库拣货 创建/执行入出库单
采购/业务只读 查询库存与单据进度 库存查询、单据查询（无改库存权限）

3. 功能需求

3.1 主数据（catalog）

  • 仓库：一等概念；单据、库位、库存余额均归属仓库。MVP 只启用一个仓库。
  • 商品（SKU）：编码、名称、规格、单位、条码、安全库存、启用状态；主数据可跨仓库共享，数量按仓库分隔。
  • 库区/库位：仓库 → 区 → 排 → 位；库位状态含空闲 / 占用 / 冻结（空间资源语义，勿与「冻结数量」混淆）。
  • 供应商/客户（轻量）：编码、名称、联系人，用于单据关联。

3.2 入库管理（inbound）

  • 支持创建入库单（采购入库 / 退货入库 / 其他入库），单据归属仓库。
  • 单据状态：草稿 → 待审核 → 已审核 → 上架中 → 已完成 / 已取消。
  • 按入库单行上架：指定库位与本次数量；支持部分上架；每次上架产生上架记录，并请求库存记账写流水。
  • 库存增加以库存上下文记账成功为准；盘点锁覆盖的库位不可上架。
  • 全部行累计上架达标后单据自动已完成。已上架数量不可靠「取消」抹掉。

3.3 出库管理（outbound）

  • 支持销售出库 / 领料出库 / 其他出库，单据归属仓库。
  • 单据状态：草稿 → 待审核 → 已审核 → 拣货中 → 已完成 / 已取消。
  • 审核 = 分配（预留）：按行将可用数量转为冻结数量；不足则拒绝或按策略拆单。
  • 拣货确认 = 预留实扣：按行从指定库位实扣；支持部分拣货；每次拣货产生拣货记录与对应库存流水。
  • 出库取消：未拣部分先释放预留；已实扣数量不可抹账，纠错走退货入库（或二期冲销）。
  • 盘点锁覆盖的库位不可拣货。

3.4 库存（inventory）

  • 库存是数量账的唯一所有者；其它上下文不得直接改账。
  • 余额维度：仓库 + SKU + 库位（MVP 不强制批次）。
  • 数量口径：在库数量、冻结数量、可用数量（= 在库 − 冻结）。
  • 提供库位库存查询、按 SKU 汇总、库存流水（须关联业务单据与单据行）。
  • 库存预警：某仓某 SKU 汇总可用量低于安全库存时生成，回升后解除；展示层只读。

3.5 盘点管理（stocktake）

  • 创建盘点单（按某仓库的库区或全仓）。
  • 盘点生效后对覆盖库位加盘点锁：禁止上架与出库（与出库「冻结数量」预留不是同一机制）。
  • 录入实盘数量；审核前差异不落账。
  • 主管审核后请求库存一次性盘盈/盘亏调整、写流水并释放盘点锁。

3.6 报表与审计

  • 日报：入出库汇总、当前库存 SKU 数、预警数。
  • 出入库明细导出（CSV）。
  • 操作日志（平台审计）：登录、单据审核等动作轨迹；与库存流水区分，不可互相替代。

3.7 系统管理（平台）

  • 用户、角色、菜单/接口级权限。
  • 登录认证（账号密码）；密码加密存储。
  • 基础字典：单位、单据类型、取消原因等。

5. 关键业务规则

  1. 任何库存增减必须经库存上下文记账，并关联业务单据与单据行写库存流水；禁止无流水改账。
  2. 出库审核只做分配（预留），拣货确认才实扣；不存在「审核只校验、中间不预留」的路径。
  3. 可用数量 = 在库数量 − 冻结数量；新的出库分配只能占用可用数量。
  4. 同一 SKU 可分布多库位；MVP 出库/上架由人工指定库位。
  5. 已完成 / 已取消单据不可再编辑；已实扣纠错不走「取消抹账」，而走退货入库或二期冲销。
  6. 盘点锁期间，被锁库位禁止上架与出库；实盘差异仅在审核通过后落账。
  7. 删除主数据采用「停用」；有历史单据的 SKU 不可物理删。
风险提示：并发出库与盘点同时进行时，必须以盘点锁阻断被盘库位的上架/拣货，否则易产生账实偏差。盘点锁 ≠ 冻结数量。

6. 用户故事（节选）

编号作为…我希望…以便…
US-01 仓管员 创建采购入库单并按行多次上架到指定库位 货物分批入账且流水可追溯
US-02 仓库主管 审核出库单完成分配预留 后续拣货不被其它单据抢走库存

US-04 仓库主管 取消已部分拣货出库单的未拣部分 释放预留且不抹掉已出库数量
US-05 仓库主管 发起盘点并在锁库位后审核盈亏 定期校正账实且盘中无并行进出
US-06 业务人员 按仓库 + SKU 查询可用库存与库位分布 承接订单前确认有货
US-07 管理员 配置角色菜单权限 最小权限原则落地

8. 验收标准（MVP）

  • 可完成：建仓库/SKU/库位 → 入库上架 → 库存可见 → 出库分配 → 拣货实扣 → 流水可按单据行查询
  • 库存不足时出库审核（分配）被正确拒绝，且无负可用/负在库
  • 两人几乎同时分配同一库存时，不会超卖（压测用例通过）
  • 部分拣货后取消未拣部分：预留释放正确，已实扣数量不变
  • 盘点锁期间被锁库位无法上架/拣货；盈亏审核后库存与流水一致
  • 低于安全库存产生预警，回升后解除
  • 无权限用户无法审核单据；关键操作写入操作日志（与流水可分别查询）
