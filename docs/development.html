仓脉 WMS 开发设计说明书

实现路径：技术栈、限界上下文落码、数据模型、API、状态机与里程碑。业务规则见 需求索引（正文 docs/requirements/*.md）；术语见 领域模型。

1. 概述与设计原则

  • 库存唯一账本：只有 inventory 上下文改数量并写 ledger；inbound / outbound / stocktake 发请求，以记账成功为准。
  • 出库软分配：审核 = 可用→冻结；拣货 = 预留实扣；取消未拣 = 释放预留。
  • 盘点锁：锁库位作业，不靠把数量记入冻结数量实现。
  • 幂等与防超卖：分配/实扣使用库存行 version 乐观锁；重复提交用业务单号 + 执行幂等键（MVP 幂等记录存 MySQL，不上 Redis）。
  • 仓库一等：表与 API 均带 warehouse_id；MVP 只启用一个仓库。
  • 交付面 ≠ 上下文：后端、网页后台、小程序是适配器；领域按 catalog / inventory / inbound / outbound / stocktake 分包。

分层约定

  • Controller：参数校验、鉴权、DTO，不含库存规则
  • Application：用例编排（如 approveOutbound → 调用库存分配）
  • Domain（按上下文）：状态机、分配/实扣/盘点锁策略
  • Infrastructure：SQLAlchemy 同步仓储、JWT（Access）、操作日志持久化

4. 模块划分

catalog · 主数据

仓库、SKU、库区库位、供应商/客户、安全库存阈值。

inventory · 库存

余额、分配/实扣/释放、流水、库存预警。唯一写库存表。

inbound · 入库

入库单/行、审核、上架记录；请求库存增加。

outbound · 出库

出库单/行、审核分配、拣货实扣、取消释放预留。

stocktake · 盘点

盘点单、盘点锁、实盘、盈亏审核请求调账。

platform · 身份与审计

用户角色、菜单权限、操作日志。非领域上下文。

5. 数据模型（核心）

5.1 ER 关系（文字版）

Warehouse 1—N Location；SKU 跨仓共享；Inventory 为（Warehouse × SKU × Location）余额；InboundOrder / OutboundOrder 1—N Line，均属 Warehouse；每次上架/拣货/盈亏写 InventoryLedger（含 ref_line_id）。

5.2 关键表（简化 DDL 示意）

CREATE TABLE warehouse (
  id              BIGINT PRIMARY KEY AUTO_INCREMENT,
  warehouse_code  VARCHAR(64) NOT NULL UNIQUE,
  name            VARCHAR(200) NOT NULL,
  status          TINYINT NOT NULL DEFAULT 1
) ENGINE=InnoDB;

CREATE TABLE sku (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  sku_code      VARCHAR(64) NOT NULL UNIQUE,
  name          VARCHAR(200) NOT NULL,
  unit          VARCHAR(16) NOT NULL,
  safety_stock  DECIMAL(18,3) NOT NULL DEFAULT 0,
  status        TINYINT NOT NULL DEFAULT 1
) ENGINE=InnoDB;

CREATE TABLE location (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  warehouse_id  BIGINT NOT NULL,
  location_code VARCHAR(64) NOT NULL,
  zone          VARCHAR(32),
  status        TINYINT NOT NULL DEFAULT 1, -- 含盘点锁等作业状态
  UNIQUE (warehouse_id, location_code),
  CONSTRAINT fk_location_wh FOREIGN KEY (warehouse_id) REFERENCES warehouse(id)
) ENGINE=InnoDB;

CREATE TABLE inventory (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  warehouse_id  BIGINT NOT NULL,
  sku_id        BIGINT NOT NULL,
  location_id   BIGINT NOT NULL,
  qty_on_hand   DECIMAL(18,3) NOT NULL DEFAULT 0,
  qty_frozen    DECIMAL(18,3) NOT NULL DEFAULT 0,
  version       BIGINT NOT NULL DEFAULT 0,
  UNIQUE (warehouse_id, sku_id, location_id)
  -- qty_available = qty_on_hand - qty_frozen（查询计算或生成列）
) ENGINE=InnoDB;

CREATE TABLE inventory_ledger (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  warehouse_id  BIGINT NOT NULL,
  sku_id        BIGINT NOT NULL,
  location_id   BIGINT NOT NULL,
  change_qty    DECIMAL(18,3) NOT NULL,
  bal_qty       DECIMAL(18,3) NOT NULL,
  ref_type      VARCHAR(32) NOT NULL,  -- PUTAWAY / ALLOCATE / PICK / RELEASE / STOCKTAKE
  ref_id        BIGINT NOT NULL,
  ref_line_id   BIGINT NULL,
  ref_no        VARCHAR(64) NOT NULL,
  operator_id   BIGINT NOT NULL,
  created_at    DATETIME(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6)
) ENGINE=InnoDB;
分配伪代码：在事务内 UPDATE inventory SET qty_frozen = qty_frozen + :q, version = version + 1 WHERE id = :id AND version = :ver AND (qty_on_hand - qty_frozen) >= :q。实扣：同步减少 qty_frozen 与 qty_on_hand。释放预留：仅减少 qty_frozen。

6. API 设计（节选）

统一前缀 /api/v1；鉴权 Header：Authorization: Bearer <token>；写接口建议带幂等键；响应包络：

{
  "code": 0,
  "message": "ok",
  "data": { },
  "traceId": "..."
}
方法路径说明
POST/auth/login登录，返回 JWT
GET/POST/warehouses仓库（MVP 只启用一个）
GET/POST/skus商品列表 / 创建
GET/POST/locations库位管理
POST/inbound-orders创建入库单
POST/inbound-orders/{id}/approve审核入库单
POST/inbound-orders/{id}/putaway上架（部分）；增在库
POST/outbound-orders创建出库单
POST/outbound-orders/{id}/approve审核 = 分配（预留）
POST/outbound-orders/{id}/pick拣货 = 预留实扣（部分）
POST/outbound-orders/{id}/cancel取消未拣：释放预留
GET/inventories按仓库/SKU/库位查询
GET/inventories/ledgers库存流水
GET/inventories/alerts库存预警
POST/stocktakes创建盘点并加盘点锁
POST/stocktakes/{id}/approve审核盈亏、调账、释锁

7. 单据状态机

入库

DRAFT→ PENDING→ APPROVED→ PUTAWAY→ DONE

未上架可转 CANCELLED。已上架数量不可靠取消抹掉；纠错走调整或二期冲销。

出库

DRAFT→ PENDING→ APPROVED→ PICKING→ DONE

APPROVED 时已完成分配。取消：释放未拣预留；若已有实扣，已出库部分保留，未拣关闭或整单按规则终结。已实扣纠错 → 退货入库。

9. 开发规范

  • 分支：main 保护；功能分支 feature/*；发版打 tag
  • 提交信息：简体中文，说明「为什么」
  • 领域用语与 领域模型 / CONTEXT.md 一致，避免「冻结」一词混用
  • 接口变更更新 OpenAPI；破坏性变更升 /api/v2
  • 配置与密钥：pydantic-settings + .env（不入库）；Compose/环境变量注入
  • 时间：DB 与 API 统一 UTC；前端/小程序展示再转本地
  • CORS：开发环境白名单本地 Vite 源；小程序不依赖浏览器 CORS
  • 库存单测/集成测必覆盖：分配不足、实扣、释放预留、乐观锁冲突、幂等、盘点锁拒绝进出（pytest + httpx）
  • 禁止在 Controller 或 inbound/outbound 包直接 UPDATE inventory
  • 操作日志与库存流水分表存储、分接口查询

11. 部署与运维要点

  • 环境：dev / staging / prod 隔离；密钥走环境变量
  • 数据库每日备份；恢复演练至少每季度一次
  • 监控：API 错误率、接口耗时、分配/实扣失败率、连接池
  • 上线检查清单：迁移脚本、回滚方案、默认仓库种子数据、初始管理员
