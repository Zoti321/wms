# 总览与全局约束

文档编号 WMS-SRS-001 · 模块 `overview` · 版本 1.2

术语与上下文边界见 [领域模型](../domain.html) / 根目录 `CONTEXT-MAP.md`。实现见 [开发文档](../development.html)。

## 目标与范围

### 背景

企业仓库依赖表格或口头交接时，易出现账实不符、库位混乱、出库差错与追溯困难。需要一套以单据驱动的数字化 WMS，统一管理入库、上架、出库、盘点与库存查询。

### 目标

- 库存账实一致率 ≥ 99.5%（按月盘点口径）
- 出入库单据全程可追溯（操作人、时间、数量、库位、库存流水）
- 支持低库存预警，减少缺货与积压
- MVP 在 8～12 周内可上线「单仓启用」的核心流程（模型仍预留多仓）

### MVP 范围内

仓库/商品/供应商/库位主数据；入库、出库（审核分配 + 拣货实扣）；库存查询与流水；盘点锁 + 简单盘点；角色权限与操作日志；基础报表与库存预警。

### MVP 范围外（二期）

PDA 扫码、波次拣货、保质期 FEFO、多仓调拨自动化、AGV/立库、与外部 ERP 深度双向同步、红冲单细化。

## 干系人与角色

角色与鉴权属**平台支撑**，不进入领域 Context Map。业务职责如下：

| 角色 | 职责 | 典型权限 |
|---|---|---|
| 系统管理员 | 账号、角色、基础配置 | 用户管理、字典配置、全模块只读/授权 |
| 仓库主管 | 审核单据、盘点、报表、异常处理 | 审核入出库、发起盘点、查看全仓报表 |
| 仓管员 | 执行入库上架、出库拣货；可在网页后台创建入出库单 | 网页后台：创建/执行入出库；**小程序作业端仅执行上架与拣货（实扣），不创建/审核单据** |
| 采购/业务只读 | 查询库存与单据进度 | 库存查询、单据查询（无改库存权限） |

## 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 常规查询 P95 < 500ms；单仓 SKU ≤ 5 万、日单据 ≤ 2000 时系统流畅可用 |
| 并发 | 分配与实扣需防超卖（乐观锁/版本号或库存行锁） |
| 可用性 | 工作日 8:00–22:00 可用；计划内维护需提前通知 |
| 安全 | HTTPS；按角色鉴权；敏感操作写操作日志；防越权 |
| 可维护 | 配置与代码分离；关键错误可追踪；支持数据备份恢复 |
| 兼容 | Chrome / Edge 近两个大版本；分辨率 ≥ 1280 宽可用；微信小程序基础库 ≥ **2.19.2** |

## 全局业务规则

跨上下文必须遵守（细节在各模块补充，不得与此冲突）：

1. 任何库存增减必须经**库存**上下文记账，并关联业务单据与单据行写**库存流水**；禁止无流水改账。
2. 出库审核只做**分配（预留）**，拣货确认才**实扣**；不存在「审核只校验、中间不预留」的路径。
3. 可用数量 = 在库数量 − 冻结数量；新的出库分配只能占用可用数量。
4. 同一 SKU 可分布多库位；MVP 出库/上架由人工指定库位。
5. 已完成 / 已取消单据不可再编辑；已实扣纠错不走「取消抹账」，而走退货入库或二期冲销。
6. 盘点锁期间，被锁库位禁止上架与出库；实盘差异仅在审核通过后落账。
7. 删除主数据采用「停用」；有历史单据的 SKU 不可物理删。

**风险：** 并发出库与盘点同时进行时，必须以**盘点锁**阻断被盘库位的上架/拣货。盘点锁 ≠ 冻结数量。

## 端到端验收（MVP 主路径）

- 可完成：建仓库/SKU/库位 → 入库上架 → 库存可见 → 出库分配 → 拣货实扣 → 流水可按单据行查询
