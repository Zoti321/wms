建设路径 版本 1.2 · 2026-08-20

做一个仓库管理系统该怎么做

先钉死领域语言与上下文边界，再写需求与落码。核心问题是：「货从哪来、放哪、怎么出、谁能改账、怎么对账」。

推荐建设步骤

  1. 领域建模
    划分主数据 / 库存 / 入库 / 出库 / 盘点；明确库存唯一账本、软分配与盘点锁（见 领域模型）。
  2. 编写并评审需求
    用统一语言写清规则与验收（见 需求文档），冻结 MVP。
  3. 架构与开发设计
    Monorepo：后端 + 网页后台 + 小程序；按上下文分包（见 开发文档）。
  4. 按里程碑迭代
    主数据 → 入库上架 → 出库分配/实扣 → 盘点锁与盈亏 → 预警与审计。
  5. 测试与上线
    覆盖分配超卖、释放预留、盘点锁互斥、流水与操作日志分离；备份与回滚预案。

MVP 建议范围

必须有

仓库（一等，单仓启用）、SKU 与库位、入库上架、出库分配+实扣、实时库存与流水、盘点锁、低库存预警、权限与操作日志。

可二期

批次/保质期、波次拣货、条码/PDA、多仓调拨、ERP 双向同步、红冲单细化。

核心业务流（一眼看懂）

采购到货→ 入库审核→ 上架入账→ 出库分配→ 拣货实扣

全程单据驱动：改账只发生在库存上下文，并留下关联单据行的库存流水。

文档约定：术语以领域模型为准；技术栈为 Vue 3 + 小程序 + FastAPI（uv / uvicorn / PyMySQL）+ MySQL 8.0。上下文边界与软分配/盘点锁为固定设计约束。
