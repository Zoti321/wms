仓脉 WMS 需求规格说明书

本文档定义仓库管理系统的业务目标、功能范围、角色权限、业务规则与验收标准，是产品设计与开发验收的依据。

1. 引言

1.1 项目背景

企业仓库依赖表格或口头交接时，易出现账实不符、库位混乱、出库差错与追溯困难。需要一套以单据驱动的数字化 WMS，统一管理入库、上架、出库、盘点与库存查询。

1.2 项目目标

  • 库存账实一致率 ≥ 99.5%（按月盘点口径）
  • 出入库单据全程可追溯（操作人、时间、数量、库位）
  • 支持低库存预警，减少缺货与积压
  • MVP 在 8～12 周内可上线单仓核心流程

1.3 范围说明

范围内（MVP）范围外（二期）
商品/供应商/库位主数据；入库、出库、库存查询；简单盘点；角色权限；操作日志；基础报表 PDA 扫码、波次拣货、保质期 FEFO、多仓调拨自动化、AGV/立库、与外部 ERP 深度双向同步

2. 干系人与角色

角色职责典型权限
系统管理员 账号、角色、基础配置 用户管理、字典配置、全模块只读/授权
仓库主管 审核单据、盘点、报表、异常处理 审核入出库、发起盘点、查看全仓报表
仓管员 执行入库上架、出库拣货 创建/执行入出库单、库位调整申请
采购/业务只读 查询库存与单据进度 库存查询、单据查询（无改库存权限）

3. 功能需求

3.1 基础数据管理

  • 商品（SKU）：编码、名称、规格、单位、条码、安全库存、启用状态
  • 库区/库位：仓→区→排→位；库位容量与状态（空闲/占用/冻结）
  • 供应商/客户（轻量）：编码、名称、联系人，用于单据关联

3.2 入库管理

  • 支持创建入库单（采购入库 / 退货入库 / 其他入库）
  • 单据状态：草稿 → 待审核 → 已审核 → 上架中 → 已完成 / 已取消
  • 审核通过后可按行指定库位上架；上架完成增加可用库存
  • 支持部分上架；完成后自动关闭单据

3.3 出库管理

  • 支持销售出库 / 领料出库 / 其他出库
  • 审核时校验可用库存；不足则拒绝或提示拆单（可配置）
  • 拣货确认后扣减库存；支持按库位出库
  • 单据状态：草稿 → 待审核 → 已审核 → 拣货中 → 已完成 / 已取消

3.4 库存与库位

  • 库存维度：SKU + 库位（MVP 不强制批次）
  • 数量口径：在库数量、可用数量、冻结数量
  • 库位库存查询、按 SKU 汇总查询、库存流水（变动明细）
  • 低于安全库存时生成预警记录并可在首页展示

3.5 盘点管理

  • 创建盘点单（按库区或全仓）；冻结相关库位可选
  • 录入实盘数量，系统计算盈亏
  • 主管审核后生成盘盈/盘亏调整，更新库存并留痕

3.6 报表与审计

  • 日报：入出库汇总、当前库存 SKU 数、预警数
  • 出入库明细导出（CSV）
  • 操作日志：登录、单据审核、库存调整关键操作

3.7 系统管理

  • 用户、角色、菜单/接口级权限
  • 登录认证（账号密码）；密码加密存储
  • 基础字典：单位、单据类型、取消原因等

4. 非功能需求

类别要求
性能常规查询 P95 < 500ms；单仓 SKU ≤ 5 万、日单据 ≤ 2000 时系统流畅可用
并发出库扣库存需防超卖（乐观锁/版本号或库存行锁）
可用性工作日 8:00–22:00 可用；计划内维护需提前通知
安全HTTPS；按角色鉴权；敏感操作写审计日志；防越权
可维护配置与代码分离；关键错误可追踪；支持数据备份恢复
兼容Chrome / Edge 近两个大版本；分辨率 ≥ 1280 宽可用

5. 关键业务规则

  1. 任何库存增减必须关联业务单据与明细行，禁止直接改库存表而无流水。
  2. 已完成 / 已取消单据不可再编辑；冲销需走红冲或调整单（二期可细化）。
  3. 可用数量 = 在库数量 − 冻结数量；出库只能扣可用数量。
  4. 同一 SKU 可分布多库位；出库默认按指定库位，未指定时由策略选择（MVP：人工选库位）。
  5. 盘点审核通过前，实盘差异不落库存；审核通过后一次性调整并记流水。
  6. 删除主数据采用「停用」而非物理删除；有历史单据的 SKU 不可物理删。
风险提示：并发出库与盘点同时进行时，必须明确「盘点冻结」策略，否则易产生账实偏差。MVP 建议：盘点中的库位禁止出库，或盘点期间全仓只读出库。

6. 用户故事（节选）

编号作为…我希望…以便…
US-01 仓管员 创建采购入库单并指定库位上架 货物及时入账可售/可用
US-02 仓管员 按出库单从指定库位拣货确认 正确扣减库存并完成发货
US-03 仓库主管 审核出入库单并查看异常 控制差错与越权操作

US-06 管理员 配置角色菜单权限 最小权限原则落地

8. 验收标准（MVP）

  • 可完成：建 SKU/库位 → 入库上架 → 库存可见 → 出库扣减 → 流水可查
  • 库存不足时出库审核/确认被正确拒绝，且无负库存
  • 两人几乎同时出库同一库位库存时，不会超卖（压测用例通过）
  • 盘点盈亏审核后库存与流水一致
  • 无权限用户无法审核单据或改库存
  • 关键操作写入审计日志，可按人/时间查询
